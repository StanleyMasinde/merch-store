## Merch Store

Merch Store is a sample Rust web application demonstrating the usage of my [Daraja SDK](https://github.com/StanleyMasinde/daraja-sdk) (an experimental Rust client for Safaricom's M-Pesa API), Axum, and Toasty ORM.

## Running

1. Clone this repo.
2. Copy `config.toml.example` to `config.toml`
3. Update `config.toml` with your Daraja credentials.
4. Run the app with `cargo run` — it will start the server at `localhost:3000`
5. You can test it with this curl command
```shell
curl  "localhost:3000/pay" --json '{"phone_number": <phone number to prompt>, "amount": 1}'
```
That's it for now.

## Database migrations

Migrations are handled by a separate `cli` binary (built from `src/bin/cli.rs`), backed by Toasty's migration system. Migration config lives in `Toasty.toml`, with generated SQL, snapshots, and history tracked under `database/`.

### Generating a migration

After changing a model struct:

```shell
cargo run --bin cli -- migration generate
```

Review the generated SQL in `database/migrations/` before committing. Commit `database/migrations/`, `database/snapshots/`, and `database/history.toml` alongside the model change.

### Applying migrations

```shell
cargo run --bin cli -- migration apply
```

By default, this reads `config.toml` from the current directory. To point at a config file elsewhere, pass `--config`:

```shell
cargo run --bin cli -- --config /path/to/config.toml migration apply
```

### Deploying (Suggestion)

In production, `merch_store` and `cli` are built once in CI (no `cargo` on the server) and shipped together via `rsync`. `config.toml` lives on the server at `/etc/merch-store/config.toml` and is never present in CI — it's provisioned once, out-of-band, and never rsynced or regenerated by the deploy pipeline.

```
/etc/merch-store/
└── config.toml

/var/lib/merch_store/
├── merch_store
└── migrations/
    ├── cli
    ├── Toasty.toml
    └── database/
        ├── history.toml
        ├── migrations/
        └── snapshots/
```

Deploy flow:

1. Build both binaries in CI (`cargo build --release`)
2. `rsync` `merch_store`, `cli`, `Toasty.toml`, and the `database/` directory to the server
3. Over SSH: `cd /var/lib/merch_store/migrations && ./cli --config /etc/merch-store/config.toml migration apply`
4. If the migration succeeds, restart the systemd service (`sudo systemctl restart merch_store`); if it fails, abort before restarting
